# Configuration, Manifest & Lockfile

Skillporter works with zero configuration flags, and supports declarative project configuration via `skillporter.yaml` and `skillporter.lock`.

## `skillporter.yaml` (Project Manifest)

Create `skillporter.yaml` with `skillporter init`:

```yaml
schema_version: 1
project: my-service
scope: project
strategy: copy
security_policy: HIGH
harnesses:
  - claude-code
  - codex
  - cursor
skills:
  - name: skillporter
    source: Shanmukh-l33t/skillporter/skills/skillporter
    ref: main
    harnesses: [claude-code, codex, cursor]
```

## `skillporter.lock` (Deterministic Lockfile)

Generated by `skillporter lock` or `skillporter sync`:

```json
{
  "schema_version": 1,
  "generated_at": "2026-11-11T06:00:00Z",
  "skills": {
    "skillporter": {
      "name": "skillporter",
      "source": "https://github.com/Shanmukh-l33t/skillporter.git#skills/skillporter",
      "resolved_commit": "ceb64c65cf5b2e261e2267f48ad7659e7c74db07",
      "version": "2.0.0",
      "tree_hash": "8f91c2a0...",
      "strategy": "copy",
      "installed_targets": ["claude-code", "codex", "cursor"],
      "locked_at": "2026-11-11T06:00:00Z"
    }
  }
}
```

## Environment Variables

| Variable | Purpose | Default |
|---|---|---|
| `HERMES_HOME` | Hermes profile home used to resolve `$HERMES_HOME/skills` | `~/.hermes` |
| `SKILLPORTER_REGISTRY_URL` | Optional local JSON path or HTTP URL for custom skill registries | Seed catalog |
| `NO_COLOR` | Disable ANSI terminal colors when set | Unset |
